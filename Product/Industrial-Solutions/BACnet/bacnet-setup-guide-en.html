EOE-W55RP20_BACnet Module BACnet Setup Guide

Firmware 1.0.0

This is the procedure for bringing an EOE-W55RP20_BACnet module in its factory state to the point where it communicates with a BACnet workstation. The workstation examples use YABE (Windows) and bacpypes3 (Python).

The module runs either BACnet/IP (Annex J) or BACnet/SC (Annex AB). It does not use both at the same time — using both at once would require the device to be a BACnet router, which is outside the scope of this release. The factory default is both off (OFF), and you first choose which one to use in §0.5.

Object definitions, device identity, time, the hub and credentials are described for both AT commands and the Web GUI. Either way gives the same result. The two use the same check functions, so they also reject the same values.

This document is written for firmware 1.0.0. Check the version in the first field of AT+VERSION?. The full format of each command and every error code are in the AT Command Guide. This document covers only the order of the first setup.

Vendor ID. The module ships with Vendor_Identifier 1697, which ASHRAE assigned to WIZnet. An integrator that sells the module as its own product can change it to the number it received from ASHRAE, together with its company name and model name (§3.1). Do not borrow another company's number.

A factory reset erases the BACnet/SC credentials (including the private key) first. This is so that no key is left behind when the module is handed over or scrapped. Object definitions, the stored CSV and PERSISTENT values are erased as well. Factory data (MAC, serial number) remains. While a firmware image is waiting to be installed, a factory reset is refused (ERROR:OTA_PENDING, and +FACTORY:ERROR,OTA_PENDING on the AT port). If the credential slots are not erased after two attempts, nothing is reset and the module does not reboot — +FACTORY:ERROR,CREDENTIALS (AT gives ERROR:STORAGE_FAILURE, the web 500). This is so that the reset does not look finished while the key remains. Try again; if it keeps happening, the flash is faulty.

Three things matter here.

The first setup must be done over AT. The Web GUI is off in the factory default. This is so that the module is not shipped with an HTTP server with a known password on the network, and it is why turning the web on cannot itself be done over the web (§2).

BACnet is off. A module in the factory state does not answer Who-Is. This is the same principle as the web being off — it sends nothing onto the network until it is turned on.

The address is STATIC 192.168.11.2. If the PC is on a different subnet, the module is not visible. In step 1, switch to DHCP or put the PC on the same subnet.

  • If the site runs a BACnet/SC hub, or traffic has to cross the internet or another building, use SC. You need the hub's address and certificates issued by the site's certificate authority.
  • Why the B/IP APDU is 1024. The W5500 does not reassemble IP fragments. Saving and applying — how AT and the web differ​

AT setting commands change only the settings in RAM. The change appears on the network after AT+SAVE. Even if you change the instance with AT+BACDEV, the device answers with the old instance until AT+SAVE — so that no client ever sees an identity that would disappear on a reset without saving.

The web's "Save and apply" saves and applies on the spot. It also saves the settings changed over AT and not yet saved — because a save writes the whole configuration at once. If you are trying something out over AT, tidy it up before saving on the web.

Exceptions to this rule:

  • Object commands are not settings. AT+BOBJADD, AT+BOBJDEL and AT+BOBJVAL are visible on the network immediately. However, the object table changed with AT+BOBJADD and AT+BOBJDEL is kept in flash only at AT+SAVE (§4.2).
  • BACnet/SC credentials are not settings, so they are written to flash as soon as they are uploaded or erased (§7).
  • Commands that replace the whole mapping save by themselves — AT+BMAPCLEAR, AT+BMAPRELOAD, and Validate and apply, Re-apply stored CSV and Clear mapping on the web Object mapping tab (§4.3).

These self-saving commands also write the whole configuration. As with the web's Save and apply, settings changed over AT and not yet saved go into flash with them. Of those, the BACnet settings (AT+BACMODE, AT+BACDEV, AT+BIP, AT+BIPFD, AT+TIMESRC, AT+BACPASS and so on) are also applied right away. Network settings (AT+IP, AT+NETMODE and so on) and web settings are only saved; they are applied at the next AT+SAVE or reboot. Before using a mapping command, commit the AT settings you were trying out with AT+SAVE, or revert them.

What you need​

  • A serial port for the AT UART (115200 8N1) — Tera Term or similar
    • That is the factory default. A board someone else has used may have a different speed
  • A PC on the same network, and one of these two BACnet workstations
    • YABE (Yet Another BACnet Explorer, Windows)
    • bacpypes3 — pip install bacpypes3 (Python 3.8 or later). The examples in this document were checked with 0.0.110
  • If you use BACnet/SC: the hub's wss:// address, and a private key, device certificate and issuer certificate (§7.1)

The examples in this document use COM11 = AT, 192.168.11.160 = module, 192.168.11.50 = PC, Device 1001 = module; substitute your own values when reading them.

1. Network​

With DHCP:

AT+NETMODE=DHCP
AT+SAVE

With a static address:

AT+NETMODE=STATIC
AT+IP=192.168.11.160
AT+MASK=255.255.255.0
AT+GW=192.168.11.1
AT+DNS=192.168.11.1
AT+SAVE

AT+SAVE saves and applies together. When the network actually changes, all open sockets are closed — if you were connected over the web or BACnet at that moment, the connection drops, and the B/IP socket and the SC hub connection are reopened on the new address. An AT+SAVE that did not touch the network (a save that changed only BACnet settings) does not close sockets.

Check the address:

AT+IP?
+IP:"192.168.11.160"

DNS is used by BACnet/SC and Foreign Device registration. If you give the hub URI, the BBMD or the SNTP server as a name, the module resolves that name with this DNS server. If you give an IP address, DNS is not used. With DHCP the module uses the DNS the DHCP server gave; if the server gives no DNS, it uses the DNS set here. Replies are accepted only from that DNS server's address, port 53 — a server that answers from a different address (behind some NATs) does not resolve names, so give the address that answers as the DNS.

If you unplug and replug the cable under DHCP, the module renegotiates at once. If it gets the same address, connections stay as they are; if it gets a different address, sockets are closed and +IPCHANGED reports the new address. If the server refuses the lease renewal (NAK), the module also renegotiates from the beginning.

On the web — Network tab​

Once the web is on (§2), the Network tab does the same thing. Mode is a DHCP/STATIC list; choosing DHCP locks the IP, Subnet mask, Gateway and DNS fields (they hold the values the DHCP server gave and are not saved). Apply and save drops every connection when the settings actually changed — including this page's session.

2. Turning on the Web GUI​

Every step after this can also be done on the web. The web is off in the factory state, so turn it on over AT first:

AT+WEBUSER="admin"
AT+WEBPASS="your-password"
AT+WEB=1,600
AT+SAVE

The 600 in AT+WEB=1,600 is the session idle time (seconds). The password must be at least 8 characters.

In a browser, go to http://<module-address>:50003/ and sign in.

Do not leave out the port number. The web UI is on 50003, not 80. If you type only the address, the browser goes to 80 and gets no answer, which looks exactly as if the web UI were not turned on.

This page is HTTP. This module does not have the memory to run TLS for the web (this is separate from the TLS of BACnet/SC). The password travels in plaintext, so use it on a network you trust.

The web server handles requests one at a time. It takes one request being processed and one waiting connection, and refuses a third simultaneous connection (TCP RST — only one socket listens on the web port, to save hardware sockets). The web pages do not run into this limit. When you call the web API from a script, send requests one at a time, and retry a little later after a refused or reset connection. Details are in chapter 12 of the AT command guide.

When you call the web API directly: JSON string escapes accept only \", \\ and \/ (anything else makes the whole request 400). Send text such as names and descriptions as plain UTF-8 — the web page's JSON.stringify() escapes only control characters and unpaired surrogates, so the page has no problem with this.

The tabs are as follows. This document mostly uses the five BACnet-related ones.

Only one session can be open at a time. When you are done, press Sign out at the end of the tab row — closing the tab is not signing out, and the session remains for the idle time. Even so, no one else is locked out: signing in with the correct password takes over the remaining session. From then on, requests from the browser that was open first are refused with 401, and that page returns to the sign-in form, which states the reason. If you signed in from another tab of the same browser, the tab opened first shares the cookie, so reading keeps working, and it returns to the sign-in form the first time it tries to save. The session also ends, and the page shows the same form, when the network settings change (AT+SAVE on the AT port, a DHCP lease change) and when the idle time runs out.

A save in progress at the moment the network settings change may be cut off without an answer. The page then shows "No reply: … the request may still have been carried out", and a little later, if the session is still alive, reloads that tab — the change may already have gone in, so check the tab's values before doing it again. If a firmware upload is cut off that way, the page asks the module again a little later. If the module answers, that file will not be installed, so the page shows a refusal (if an update received earlier is waiting for a restart, it says that too); if there is no answer — the module may be restarting to install the file it received — the message stays as it is.

3. BACnet/IP — making the module visible to a workstation​

3.1 Method A — AT commands​

AT+BACMODE=BIP
AT+BACDEV=1001,"AHU-1 Controller"
AT+BACVENDOR=1697,"WIZnet","EOE-W55RP20_BACnet"
AT+SAVE

The AT+BACVENDOR line is the factory default and can be left out. If you sell the module as your own product, put your own Vendor ID, company name and model name here — the three values are a single statement, so always write them together (a Vendor_Identifier with another company's Vendor_Name is worse than both being the defaults).

The difference before and after saving:

AT+BACDEV=1001,"AHU-1 Controller"
OK
AT+BACDEV?
+BACDEV:1001,"AHU-1 Controller"
+BACDEV:APPLIED,1193046,"EOE-W55RP20_BACnet-123456"     ← the identity it answers with now
OK
AT+SAVE
OK
AT+BACDEV?
+BACDEV:1001,"AHU-1 Controller"                       ← one line once the two match
OK

The APPLIED line appears only when the setting and the actual state differ. The OK of AT+SAVE means the save is finished; the new identity is applied by the BACnet task after that (tens of ms). So an AT+BACDEV? sent right after the OK may still show the APPLIED line — ask again a little later, and if it is still there, AT+SAVE was not done. If a host program confirms the save with this line, do not decide from a single look right after AT+SAVE; ask again after a short interval. When the instance or the name changes, the device broadcasts I-Am again.

Check:

AT+BACMODE?
+BACMODE:BIP,RUNNING
AT+BIP?
+BIP:47808,SUBNET,192.168.11.160,192.168.11.255

The second field of +BACMODE: is whether the data link is actually running. Between AT+BACMODE= and AT+SAVE, and for the tens of ms right after the save while the BACnet task applies it, the setting (first field) and the state may differ — OFF,RUNNING means "told to turn off and still turning off". The last two fields of +BIP: are the address of the socket open now and the actual broadcast address; with no socket they are 0.0.0.0.

To change the UDP port and the broadcast method:

AT+BIP=47808,SUBNET        subnet-directed broadcast (default, recommended)
AT+BIP=47808,GLOBAL        255.255.255.255
AT+SAVE

If you leave out the broadcast method, the current value is kept. A UDP port equal to the web port (50003) is refused (ERROR:INVALID_PARAMETER) — the W5500 uses one port space for TCP and UDP, so whichever opens later fails.

For the same reason, if an AT+SOCKOPEN channel holds the B/IP port as its local port, the B/IP socket does not open (+BACMODE:BIP,STOPPED). The module retries this by itself — after 5 seconds, then at intervals that double each time up to 60 seconds, until the port is released and the socket opens. Meanwhile the socket field of +DIAG:BIP is RETRY and the last field is the errno of the failure (112 for a port conflict) (§10).

3.3 Checking — bacpypes3​

Start the bacpypes3 console on the PC. The PC side must also use UDP 47808 — the module's broadcast I-Am goes to 47808, so a client listening on another port does not hear the answer to a broadcast Who-Is. --instance is any number that does not clash with the module.

$ python -m bacpypes3 --address 192.168.11.50/24 --instance 999001
> whois
1001 192.168.11.160
> whois 192.168.11.160
1001 192.168.11.160
> read 192.168.11.160 device:1001 object-name

> read 192.168.11.160 device:1001 object-list
[(<ObjectType: device>, 1001), (<ObjectType: network-port>, 1)]
> read 192.168.11.160 device:1001 max-apdu-length-accepted

Giving an address, as in whois 192.168.11.160, sends a unicast Who-Is, and the module also answers with a unicast I-Am — on a network where broadcasts are blocked, this is the reliable way.

3.4 Checking — YABE​

This is for YABE 2.1.0.

  1. Start YABE and choose Functions → Add BACnet Channel (the same as the Add Channel button on the toolbar). The BACnet Communication Channel window opens.
  2. In the General box at the top of the window, change Timeout to 3000 (default 500). Leave Retries at 1 and Send WhoIs checked.
  3. In the BACnet/IP V4 & V6 over Udp box, leave Port at BAC0 (hex, = 47808), and for Local endpoint choose the PC address on the same subnet as the module (192.168.11.50).
  4. Press that box's Start (to the right of the Port line). The window has five Start buttons (BACnet/IP · SC · MSTP · PTP · Ethernet) — pressing the Start of another box opens a different kind of channel.
  5. A Udp channel appears under Network View in the Devices tree at the top left, and Device 1001 appears under it. Click it and the Objects pane at the bottom left shows the Device object and the Network Port object; click an object and its properties appear in the Properties pane on the right. The Device and Network Port objects are read-only: they are configured over AT or the web (§3.5).

Why raise Timeout to 3000. YABE's default of 500 ms is shorter than the 750 ms the module waits for the host's approval on a confirmed write (§4.5). Left as it is, YABE times out before the module answers. Changing DefaultTimeout in Options → Settings to 3000 makes it the initial value of this window.

If only a COM port name such as COM3 appears in the tree and the log shows Mstp source address must be set up before sending messages, you pressed the Start of the MSTP box. Right-click that channel → Remove Channel/Device to remove it, and start again from step 1.

Do not run YABE and bacpypes3 on 47808 on the same PC at the same time. Only one program can open a UDP port, so the one started later receives nothing. Close one and use the other.

4. Object definitions — putting host values on BACnet​

4.1 Rules​

The host MCU can define nine kinds of objects.

The type can be written as the short name, the name or the number (AI = analog-input = 0). AT and CSV read it with the same function.

Flags — the fifth argument (AT); in CSV, each flag has its own column.

FlagMeaningConstraint
C commandableHas a priority array (1 to 16)AO, BO and MSO are always C. Cannot be given to an Input

  • The Present_Value of a commandable object is set by the priority array. If the host puts a value with AT+BOBJVAL, the answer is ERROR:ACCESS_DENIED (the states FAULT/OK can be put — §4.4). The priority array does not survive a reboot — after a restart the object starts from Relinquish_Default.
  • There can be up to 256 objects, of which up to 64 commandable. Names are up to 31 bytes and must be unique within the device (including the names of Device and Network Port).

4.2 Method A — AT commands​

AT+BOBJADD=AI,1,"Supply Temp",degrees-celsius,P
AT+BOBJADD=AV,1,"Setpoint",degrees-celsius,W
AT+BOBJADD=AO,1,"Damper",percent,F
AT+BOBJADD=BO,1,"Fan Cmd"
AT+BOBJADD=BV,2,"Pump Enable",,WF
AT+BOBJADD=MSV,1,"Mode",3,W
AT+SAVE

Arguments:

AT+BOBJADD=<type>,<instance>,"<name>"[,<units|number of states>[,<flags>]]

Positions are not guessed from the number of arguments. A binary object has no fourth argument, but to give flags, keep the comma (AT+BOBJADD=BV,2,"Pump Enable",,WF).

If you leave out AT+SAVE, objects created with AT+BOBJADD disappear at the next reboot. AT+BOBJADD and AT+BOBJDEL change only the running object table; they are folded into the stored mapping at AT+SAVE. An object is visible on the network as soon as it is created (Database_Revision goes up by 1).

The other properties of an object created over AT are defaults — no write range limit, COV_Increment 0, Relinquish_Default 0.0 / INACTIVE / 1, no Description, Polarity NORMAL. To set them, use CSV (§4.3).

Check:

The list is in object identifier order. AO 1 was given only F but shows as CF — AO is always commandable.

With 256 objects the answer is ERROR:OBJECT_LIMIT; with 64 commandable objects, ERROR:COMMAND_SLOTS.

Deleting:

AT+BOBJDEL=AI,1
AT+SAVE

An object that does not exist gives ERROR:OBJECT_NOT_FOUND.

The header of the stored mapping is shown with AT+BMAP?:

AT+BMAP?
+BMAP:MANUAL_AT,6,1,0,0x00000000,<generation>

The fields are the source (DEFAULT, MANUAL_AT, CSV_IMPORT, CSV_IMPORT_MODIFIED), the object count, the CSV schema version, the size of the original CSV, its CRC, and the generation number. It reports what is stored, so after AT+BOBJADD and before AT+SAVE it shows the old count — the running table is AT+BOBJ?. The generation number changes every time the stored mapping changes, so you can tell a different mapping even when the count is the same. If you edit over AT a table uploaded as CSV and save it, the source becomes CSV_IMPORT_MODIFIED (the size and CRC of the original CSV remain, for tracking the source).

4.3 Method B — Web GUI (CSV upload)​

Quotes — a field containing a comma or a line break is enclosed whole in double quotes, and a " inside it is written as "" (the way spreadsheets save, read the same way as Python csv). A double quote opens a field only when it is the field's first character (spaces and tabs after the comma are skipped). A " anywhere else is an ordinary character, so a description such as 12" pipe is read as written. Line ends can be CRLF or LF, but a CR that is not at a line end stays in the field as a character and is refused as a control character. Control characters are C0 (including tab and line feed), DEL and C1 (U+0080 to U+009F, for example NEL) — the same rule as AT+BOBJADD.

3) Validate only — press this first. Nothing changes — the file being checked goes to a separate scratch area, and both the running objects and the stored CSV stay as they are.

A good file is answered with "The file is valid; nothing was changed. 6 row(s), 6 valid object(s), 0 error(s)". A bad file gets the reason for each row:

Row 4, Column units: unknown engineering units
Row 5, Column commandable: commandable must be Y or N, and an input cannot be commandable

Row numbers count the header as row 1, so the first data line is row 2. Up to 32 errors are listed. An empty line takes a row number, but is not counted in the "N row(s)" of the result. An error beyond row 65,535 is reported as Row 65535 or later (this happens only with a large file stored without checking).

If even one row is wrong, nothing is applied — there is no partial apply. A file with more than 256 objects, or more than 64 commandable objects, is also refused at the check stage (you never find out only after applying).

4) Validate and apply — press it after the check passes. Confirm the prompt "Replace every object with the contents of <file>?", and the mapping changes at once and the original CSV is stored.

A new object starts with a start value until the host sets one. Right after a CSV is applied or an object is created with AT+BOBJADD, the value is 0 for an analog object (or the nearer bound if its range does not include 0 — AV 1 in the example starts at 10), INACTIVE for a binary object and 1 for a multi-state object. A commandable object (AO 1, BO 1) reads its relinquish_default. The web Objects tab marks input objects "(not yet set by the host)". The value changes when the host sets it with AT+BOBJVAL (§4.4) — the CSV has no column for the present value.

Applying a CSV replaces all existing objects. It does not add only some — objects created over AT disappear too. This is why you Export the current ones first.

Validate and apply checks the file before storing it. A file this button refuses does not touch the stored CSV, so a later Re-apply applies the previous file as before. However, a file over 124 KiB has no room to be checked in advance. Validate only refuses such a file with Too Large To Check (413), and Validate and apply asks first — it sends the file only if you confirm "Store it in place of the stored CSV and then check it?". If a file sent that way is refused, that file takes the place of the stored CSV, so Re-apply is refused too (AT+BMAPRELOAD gives INVALID_CSV, and the page shows that warning); if the transfer is cut off or the flash write fails, no stored CSV remains at all (CSV_NOT_AVAILABLE). The objects in use change only if that file is valid. A host that uploads directly through the web API chooses this behaviour only with POST /api/mapping/upload?unchecked=1 — an install over 124 KiB without that mark gets 413 Too Large To Check, and the stored CSV stays as it is.

4.4 The host puts values in​

AT+BOBJVAL=AI,1,21.5               analog: real number

FAULT sets the FAULT bit of Status_Flags, and OK clears it. The state-only form is used to report a fault on a commandable object — its value comes from the priority array, so the host cannot put it, but the host knows whether there is a fault.

For an object whose Out_Of_Service the network has set to TRUE, every type gives ERROR:ACCESS_DENIED — the value during that time is the one the workstation puts in to test. When Out_Of_Service is cleared, an Input returns to the last host value before it.

When a remote write arrives at an IMMEDIATE object, the module commits it at once and only notifies the host:

+BACWRITE:AV,1,0,22.5            <type>,<instance>,<priority>,<value>
+BACWRITE:BO,1,10,ACTIVE         commandable object: the priority written

The priority is 0 if the object is not commandable. A write of the same value again sends no notification. If notifications pile up faster than the UART can carry them, they are merged and sent once as "the value in effect now" (the deferred and coalesced counts of +DIAG:BACNOTIFY are those numbers).

PERSISTENT values and power loss. The value of a PERSISTENT object is kept in the runtime journal (flash), but to avoid wearing the journal out, only one record per object per 10 seconds is written. This is the same for AT+BOBJVAL and for a workstation's WriteProperty.

  • A value that changes for the first time since the last 10-second tick is written at once.
  • A value that changes again within the same 10 seconds stays in RAM, and only the last value is written at the next tick.
  • So even a value that got an OK or a SimpleACK may be missing from flash for up to about 10 seconds. If power is cut, or a reset pin or watchdog reset comes, during that time, the object comes back after the reboot with the last recorded value. If you send AT+BOBJVAL=AV,1,272 right after AT+BOBJVAL=AV,1,271 and power is cut within a few seconds, the value after the reboot is 271, even though both got OK. Values are never mixed or corrupted.
  • AT+SAVE, AT+REBOOT, AT+OTAREBOOT, a reboot or post-update restart from the web, and ReinitializeDevice write all held values before restarting. A power cut gives no chance to do so.
  • If the host knows power is about to be cut, it waits at least 10 seconds after the last write, or sends AT+SAVE (AT+SAVE also rewrites the configuration, so do not call it for every value).

The Objects tab of the Web GUI shows the same table — type, instance, name, Present value, Units/states, Flags, Status flags, Active priority. The values belong to the host and the BACnet clients, so they are not written from this tab.

4.5 CONFIRMED objects — +BACWRITE and AT+BWRACK​

An object with flag F (write_mode=CONFIRMED in CSV) commits a remote write only after the host approves it. Use it for values that cause real action, such as relays or valves.

Sequence:

  1. The workstation sends WriteProperty
  2. The module asks over AT: +BACWRITE:<tid>,<type>,<instance>,<priority>,<value> — the tid comes first
  3. The host answers: AT+BWRACK=<tid>,OK (approve) or AT+BWRACK=<tid>,<error> (reject)
  4. The module sends a SimpleACK or an Error to the workstation
  5. If there is no answer within 750 ms, an Error (DEVICE, OPERATIONAL_PROBLEM) goes to the workstation, and a late answer gets ERROR:HOST_TIMEOUT (for the most recently expired write — see below)
(workstation) write 192.168.11.160 analog-output:1 present-value 40 8
+BACWRITE:1,AO,1,8,40
AT+BWRACK=1,OK
OK
(workstation) SimpleACK — measured about 30 to 45 ms

(workstation) write 192.168.11.160 analog-output:1 present-value 90 8
+BACWRITE:2,AO,1,8,90
AT+BWRACK=2,VALUE_OUT_OF_RANGE   ← the host refuses (e.g. the equipment opens only to 80%)
OK
(workstation) Error: property / value-out-of-range

(workstation) write 192.168.11.160 analog-output:1 present-value null 8
+BACWRITE:3,AO,1,8,NULL          ← priority 8 released (relinquish)
AT+BWRACK=3,OK

A value outside the range is not sent to the host. When an object has min and max (AO 1 in the §4.3 CSV is 0 to 100) and a value outside that range arrives, the module refuses it at once with Error (property / value-out-of-range), and no +BACWRITE is sent. The host's refusal is for a value that is inside the range but that the equipment cannot accept.

There are three words for a rejection, and they reach the workstation with error class PROPERTY.

Second argument of AT+BWRACKWhat the workstation receives
OKSimpleACK, value committed
WRITE_ACCESS_DENIEDError property / write-access-denied
VALUE_OUT_OF_RANGEError property / value-out-of-range
INVALID_DATA_TYPEError property / invalid-data-type

Any other word is refused, not taken as a rejection (ERROR:INVALID_PARAMETER) — a typo of OK must not reject a write the host meant to approve.

AT+BWRACK=4,OK                   (after 750 ms have passed)
ERROR:HOST_TIMEOUT               ← too late. The workstation has already received an Error

AT+BWRACK=77,OK
ERROR:OBJECT_NOT_FOUND           ← no write is waiting with that tid (already answered, or a number never issued)

AT+BWRACK=0,OK
ERROR:VALUE_OUT_OF_RANGE         ← the tid is 1 to 65535
  • The module does not stop while waiting for the answer. A pending write is kept separately, and other requests are handled as usual in the meantime. Up to 4 writes can wait at the same time; a fifth gets an Error (RESOURCES, NO_SPACE_TO_WRITE_PROPERTY) at once.
  • HOST_TIMEOUT means "answer faster", and OBJECT_NOT_FOUND means "you are answering the wrong thing". That is why the two are not merged into one error.
  • The module remembers only the most recently expired write for HOST_TIMEOUT, however. A late answer to a write that expired before that one gets OBJECT_NOT_FOUND. If several writes ran late together, an OBJECT_NOT_FOUND can also mean a timeout.
  • A WritePropertyMultiple that includes a CONFIRMED object is refused (to prevent only part of it being committed).
  • A write to an object that is Out_Of_Service is not passed to the host — the purpose of Out_Of_Service is to try commands without moving the equipment.
  • Priority 6 is reserved for Minimum On/Off, so writes to it are refused (write-access-denied).

In the Web GUI you only define CONFIRMED (the write_mode of the CSV). Approval is the host MCU's job, so it is done only over AT.

5. From another subnet — Foreign Device registration​

If the workstation is on another IP subnet and the module's subnet has no BBMD, register the module with a remote BBMD as a Foreign Device. While it is registered, every broadcast the module sends (I-Am and others) is also passed to the BBMD as Distribute-Broadcast-To-Network and spreads to the other subnets. This is used only in B/IP mode. (This module does not itself become a BBMD.)

5.1 Method A — AT commands​

AT+BIPFD="192.168.20.1",47808,300

6. Time — BACNET / SNTP / BOTH, UTC offset​

The module has no battery-backed clock. After every reboot the time is "unknown", and until a time source first sets it, Local_Time and Local_Date read as unspecified — the module does not give 1970 or a guessed value. The time is also used for the BACnet/SC certificate validity check (§7.6).

6.1 Choosing the time source​

Time sourceBACnet (UTC)TimeSynchronizationSNTPWhen to use
NONEIgnoredNot doneWhen no time is needed. Saving it also clears a clock already known
BACNET (default)Sets the clockNot doneWhen the site has a time master (BMS). No server setup needed
SNTPIgnoredEvery intervalWhen an NTP server can be reached
BOTHOnly when SNTP has never succeeded or has been silent for 2 × intervalEvery intervalSNTP first, BACnet when SNTP drops out

Use SNTP when the clock must be accurate. The module carries its clock forward from the last time it received on the chip's crystal oscillator, so it drifts by the crystal's error — about +90 ppm on the board measured, about 8 s a day. SNTP and BOTH fetch the time again every interval and remove the difference (a little over 0.3 s at the default 3600 s). With the BACNET source alone the drift accumulates until the workstation synchronizes the clock again.

6.2 Method A — AT commands​

  • The interval is 64 to 65535 seconds (default 3600). Outside that range, ERROR:VALUE_OUT_OF_RANGE.
  • A server or interval left out keeps its current value. So changing only the time source takes one argument (AT+TIMESRC=BOTH). "", with only the quotes, clears the server.

UTC offset — mind the sign​

BACnet's UTC_Offset is "the minutes that, added to local time, give UTC". So east is negative — Korea (UTC+09:00) is −540. To avoid confusion, both forms are accepted:

AT+UTCOFFSET=-540                minutes with the BACnet sign
AT+UTCOFFSET="UTC+09:00"         the ISO 8601 sign people use — the same value
AT+UTCOFFSET?
+UTCOFFSET:-540,"UTC+09:00"

The range is ±1440 minutes; outside it, ERROR:VALUE_OUT_OF_RANGE. "+05:30" and "UTC" also work.

With the BACNET time source the offset must be right. TimeSynchronization carries local time, so the module computes UTC with this offset. If the module receives Korean time while the offset is 0, the clock is 9 hours off. UTCTimeSynchronization carries UTC as it is. Daylight_Savings_Status is always FALSE — in regions with daylight saving time, change the offset to match.

A time earlier than 2026 is taken as a fault of the time master and is not accepted (it is counted in ignored of +DIAG:TIME).

6.4 Sending the time from a workstation​

With the BACNET time source, a workstation's TimeSynchronization sets the clock. Use the time synchronization function of a workstation such as YABE. The bacpypes3 console has no command for it, so use bac_tools.py below (it is also used for DCC/RD in §8).

# bac_tools.py - DeviceCommunicationControl, ReinitializeDevice and
# TimeSynchronization from bacpypes3 (its console has no command for them).
#   python bac_tools.py <device ip[:port]> <command> [password] [-- bacpypes3 options]
#   command: timesync | dcc-disable-initiation | dcc-enable | dcc-disable
#            | warmstart | coldstart   (dcc-disable only shows the refusal)
import asyncio, datetime, sys
from bacpypes3.argparse import SimpleArgumentParser
from bacpypes3.app import Application
from bacpypes3.pdu import Address
from bacpypes3.primitivedata import CharacterString, Date, Time
from bacpypes3.basetypes import DateTime
from bacpypes3.apdu import (DeviceCommunicationControlRequest,
                            ReinitializeDeviceRequest,
                            TimeSynchronizationRequest, ErrorRejectAbortNack)

argv = sys.argv[1:]
opts = argv[argv.index('--') + 1:] if '--' in argv else []
argv = argv[:argv.index('--')] if '--' in argv else argv
DEV, CMD = Address(argv[0]), argv[1]
PW = argv[2] if len(argv) > 2 else None


async def main():
    app = Application.from_args(SimpleArgumentParser().parse_args(opts))
    await asyncio.sleep(1)          # let the UDP endpoint come up first
    try:
        if CMD == 'timesync':
            now = datetime.datetime.now()       # this PC's local time
            req = TimeSynchronizationRequest(time=DateTime(
                date=Date((now.year - 1900, now.month, now.day,
                           now.isoweekday())),
                time=Time((now.hour, now.minute, now.second, 0))))
        elif CMD.startswith('dcc-'):
            req = DeviceCommunicationControlRequest(enableDisable=CMD[4:])
            if CMD != 'dcc-enable':
                req.timeDuration = 10           # minutes
        else:
            req = ReinitializeDeviceRequest(reinitializedStateOfDevice=CMD)
        if PW is not None and CMD != 'timesync':
            req.password = CharacterString(PW)
        req.pduDestination = DEV
        try:
            ack = await app.request(req)
            print('sent' if CMD == 'timesync' else type(ack).__name__)
        except ErrorRejectAbortNack as e:
            print('refused:', e)
        await asyncio.sleep(0.5)
    finally:
        app.close()

asyncio.run(main())

  • By default the peer is checked by its issuer (Annex AB.7.4). To also check the host name in the hub certificate, use AT+BSCHOSTCHECK=ON and AT+SAVE (web: BACnet/SC tab). With it on, a certificate that does not contain it is refused with CERT (detail 0x00000004). If the URI is a DNS name, that name is sent as SNI; if it is an IPv4 address, no SNI is sent.

Checking on the PC before uploading cuts down the reasons for a refusal:

$ openssl pkey -in dev_key.pem -noout -text | head -1          # "Private-Key: (256 bit, ...)"
$ openssl x509 -in dev.pem -noout -subject -issuer -dates
$ openssl x509 -in dev.pem -noout -fingerprint -sha256         # must equal the fingerprint in AT+BSCCERT?

7.2 Hub URI and mode — Method A, AT​

AT+BSCHUB="wss://hub1.example.com/hub","wss://hub2.example.com/hub"
AT+BACMODE=SC
AT+SAVE
+BSC:DISCONNECTED,CREDENTIALS    ← the credentials are not uploaded yet (§7.3)

There is an order. Mode SC is refused when there is no primary hub — a device with nowhere to connect would stay off the network forever. The credentials are not a condition — they may come after the mode, and until they come, the hub connector says so with +BSC:DISCONNECTED,CREDENTIALS.

AT+BACMODE=SC
ERROR:URI                        ← the hub first (AT+BSCHUB)

URI rules:

AT+BSCHUB="ws://10.0.0.9:443"
ERROR:URI                        ← wss:// only
AT+BSCHUB="wss://user:pw@10.0.0.9"
ERROR:URI                        ← user information is not accepted
AT+BSCHUB=,"wss://10.0.0.9"      (when the primary is wss://10.0.0.9)
ERROR:URI                        ← the failover is the same as the primary
  • If the port is left out, it is 443. IPv6 addresses and #fragment are not accepted. Each URI is up to 127 characters.
  • An empty argument keeps the current value: AT+BSCHUB=,"wss://b" changes only the failover. Two long URIs do not fit in one command line (255 characters), so write them separately like this. "", with only the quotes, clears that field (the primary only when the mode is not SC).
AT+BSCHUB?
+BSCHUB:"wss://hub1.example.com/hub","wss://hub2.example.com/hub"

Timers (seconds) — normally leave them at the defaults:

AT+BSCTIME=<heartbeat>,<connect wait>,<disconnect wait>,<min reconnect>,<max reconnect>
AT+BSCTIME?
+BSCTIME:300,10,10,2,30

A timer of 0, or a min reconnect below 2 seconds or larger than max, gives ERROR:VALUE_OUT_OF_RANGE. The primary is always tried first, and the failover when it fails; if both fail, the module waits starting at min and doubling up to max. While attached to the failover, it still checks the primary periodically and moves back to the primary when it returns.

With no Ethernet link, it does not dial. At boot the PHY link comes up in about 2 seconds, and the hub connection starts then — the time spent waiting for the link is not counted as an attempt, and the delay above is not used. The same holds while the cable is unplugged.

7.3 Uploading credentials — Method A, AT (chunked upload)​

An item is uploaded like this:

AT+BSCCERT=<KEY|CERT|CA1|CA2>,<total bytes>                 start
AT+BSCCERTW=<item>,<offset>,<length>                        one chunk (1 to 1024 B)
>                                                           ← exactly <length> bytes after the prompt

The > prompt has no line end. After seeing the prompt, send that part of the file as it is (PEM line breaks as they are, DER byte for byte). An example that sends a 664-byte certificate in 300-byte chunks:

AT+BSCCERT=CERT,664
OK
AT+BSCCERTW=CERT,0,300
> (300 bytes)
+BSCCERTW:CERT,300,664
OK
AT+BSCCERTW=CERT,300,300
> (300 bytes)
+BSCCERTW:CERT,600,664
OK
AT+BSCCERTW=CERT,600,64
> (64 bytes)
+BSCCERTW:CERT,STORED,MATCH,INCOMPLETE
OK

When the last chunk arrives, the module converts and checks the item, then writes it to flash. The two fields of the response are whether KEY and CERT form a pair (MATCH/MISMATCH; - if either is missing) and whether the three things needed to connect to the hub (KEY, CERT, CA1) are all present (COMPLETE/INCOMPLETE).

Uploading all three items:

AT+BSCCERT=KEY,241
AT+BSCCERTW=KEY,0,241
> (241 bytes)
+BSCCERTW:KEY,STORED,-,INCOMPLETE
AT+BSCCERT=CERT,664
AT+BSCCERTW=CERT,0,664
> (664 bytes)
+BSCCERTW:CERT,STORED,MATCH,INCOMPLETE
AT+BSCCERT=CA1,421
AT+BSCCERTW=CA1,0,421
> (421 bytes)
+BSCCERTW:CA1,STORED,MATCH,COMPLETE
+BSC:CONNECTED,PRIMARY           ← if the mode is already SC, it connects at once

Credentials do not need AT+SAVE. They are not settings, so they are written to flash as soon as they are complete, and the hub connector reconnects with the changed credentials. Checking the key and certificate and writing to flash take about 0.2 to 0.3 seconds, so the response to the last chunk comes later than for the other chunks.

What is refused:

AT+BSCCERT=KEY,5000
ERROR:BUFFER_TOO_LONG            ← an item is up to 4096 bytes

AT+BSCCERTW=KEY,0,306            (P-384 key)
ERROR:CRED_INVALID               ← not PEM/DER, does not parse, or not P-256

AT+BSCCERTW=CERT,0,668           (certificate for a different key)
ERROR:CRED_MISMATCH              ← not a certificate for the stored KEY
  • When changing KEY and CERT together, upload KEY first. A new KEY is accepted even if it does not pair with the old CERT (shown as MISMATCH; the module does not connect meanwhile), and it becomes MATCH when the matching CERT arrives. Conversely, a CERT that does not match the stored KEY cannot be used, so it is refused.
  • If the host stops in the middle of the chunks, the result is ERROR:PAYLOAD_TIMEOUT and the upload is released. Start that item again from AT+BSCCERT=.
  • If you lost a response, you may send the same chunk again (same offset and length). This also holds for the last chunk, which completed the item — the module gives the first response again.
  • The offset must continue from what has been received, or repeat the previous chunk. Otherwise the command is refused before the prompt — so that the data you send is not thrown away.
  • AT+BSCCERT=ABORT releases an open upload. An upload with no chunk for 60 seconds is discarded when another upload or a deletion asks for its place.
  • The AT port must be 8-bit and not XON/XOFF. On a port set to 7 bits or XON/XOFF, AT+BSCCERTW gives ERROR:NOT_SUPPORTED (binary cannot pass).

Check:

AT+BSCCERT?
+BSCCERT:KEY,PRESENT,P256,MATCH
+BSCCERT:CERT,PRESENT,448,P256,56:08:8A:…:83:2D:EB,"sc-device","Site CA","2020-01-01T00:00:00Z","2045-01-01T00:00:00Z"
+BSCCERT:CA1,PRESENT,421,P256,0D:D5:66:…:6B:85:CE,"Site CA","Site CA","2020-01-01T00:00:00Z","2045-01-01T00:00:00Z"
+BSCCERT:CA2,ABSENT
+BSCCERT:STORE,A,3,4,3,0
OK

A certificate line gives the DER length, the key type, the SHA-256 fingerprint (in the same format as openssl's -fingerprint -sha256), the subject CN, the issuer CN and the validity period (UTC). The last line gives the slot in use (A/B), the sequence number, the generation, and the number of writes and failures since boot.

The private key does not come out by any route. The KEY line states only three things: that it is present, whether it is P-256, and whether it pairs with CERT — no length, no fingerprint. The web is the same, and nothing goes into the logs either. If the key is lost, the only way is to get a new one and upload it. A factory reset erases all four items.

Deleting:

AT+BSCCERT=CA2,DEL
OK

Deleting any of KEY, CERT or CA1 ends the connection, and the state becomes +BSC:DISCONNECTED,CREDENTIALS.

7.6 Certificate validity policy — LENIENT / STRICT and the deadlock rule​

TLS checks a certificate's validity period against the clock. But this module does not know the time after a reboot (§6). You choose what to do while the time is unknown:

PolicyWhile the time is unknownOnce the time is known
LENIENT (default)Connects without checking the dates. The last field of AT+BSCSTATUS? is TIME_UNKNOWNChecks the dates of the kept hub certificate and of its own certificate at that point. If they are out of range, it drops the connection → +BSC:DISCONNECTED,CERT_EXPIRED
STRICTDoes not connect → +BSC:DISCONNECTED,TIME_UNKNOWNConnects after the normal check
AT+BSCVALIDITY=STRICT
AT+BSCVALIDITY?
+BSCVALIDITY:STRICT
AT+SAVE

On the web, this is Certificate validity while the time is unknown in the Time panel of the BACnet tab.

Deadlock rule. Mode SC + STRICT + time source BACNET (or NONE) never connects — STRICT does not attach to the hub until the time arrives, and BACnet time synchronization can arrive only through the hub. So this combination is refused whichever command tries to create it:

(mode SC, time source BACNET)
AT+BSCVALIDITY=STRICT
ERROR:INVALID_PARAMETER

(mode SC, STRICT)
AT+TIMESRC=BACNET
ERROR:INVALID_PARAMETER

(STRICT, time source BACNET)
AT+BACMODE=SC
ERROR:INVALID_PARAMETER

The web refuses the same cases with 400 Time source cannot reach the hub (on both the BACnet tab and the Time panel). BOTH is allowed in this combination only when there is an SNTP server.

To use STRICT, set up SNTP first:

AT+TIMESRC=SNTP,"pool.ntp.org"
AT+BSCVALIDITY=STRICT
AT+SAVE

Which to choose:

  • LENIENT — sites with no time source before the hub is reached (sites where the time comes only over BACnet). The check is done when the time arrives, so the module does not stay attached with an expired certificate.
  • STRICT — sites that can reach an SNTP server, when the module must never once connect with an expired or forged certificate.

If, with the time known, its own certificate (CERT) is outside its validity period, the module stops with CREDENTIALS (detail = verification flags) before it even dials the hub. A BACnet time synchronization received through a certificate that was refused for its dates is forgotten — it may come from a time master with the wrong date (forgotten of +DIAG:TIME).

8. DCC / ReinitializeDevice password​

A BACnet client can silence the device with DeviceCommunicationControl (DCC) and restart it with ReinitializeDevice (RD). Without a password, any client can do this — and that is the factory default. Set one before the device goes on site.

8.1 Method A — AT commands​

AT+BACPASS="s3cret-Pw"
AT+SAVE
  • It is 1 to 20 bytes (counted in UTF-8). 21 bytes or more gives ERROR:BUFFER_TOO_LONG. With only English letters, digits and symbols, the number of bytes equals the number of characters. With characters that take several bytes each, such as Korean, a password of 20 characters or fewer is still refused by both AT and the web if it is over 20 bytes (the BACnet request side counts characters and could accept it, but it cannot be set). Setting an ASCII password is recommended.
  • AT+BACPASS="" clears it. Nothing at all, as in AT+BACPASS=, is taken as a mistake and refused (ERROR:INVALID_PARAMETER) — removing the only protection requires writing the quotes.
  • There is no query command. Only a salted SHA-256 hash is stored, and neither the salt nor the hash leaves the device. If you forget the password, set a new one.
  • Like the other BACnet settings, it takes effect at AT+SAVE.

8.2 Method B — Web GUI​

9. Firmware update (OTA)​

The update file is a single w55rp20_app_<version>.fwpkg (for example w55rp20_app_1.0.0.fwpkg). The module checks the header first and receives the file into the staging area; at the next boot the bootloader verifies the image to the end and only then installs it. If reception fails or is cut off midway, the current firmware keeps running. The step-by-step procedure that follows the screens is in the Firmware Update Guide.

  • A package whose product ID differs from the module's (the fourth field of AT+VERSION?, 0x454F4502 for the BACnet edition) is refused. A package for the SNMP edition does not install on this module, and the reverse is also true.
  • Settings, BACnet/SC credentials, object definitions and PERSISTENT values remain.
  • The stored original object CSV is erased — because the staging area is shared with the firmware image. The running objects stay as they are and Export works, but Re-apply (AT+BMAPRELOAD) gives CSV_NOT_AVAILABLE. If you need the CSV, Export it before updating.

9.1 Method A — Web GUI​

On the Firmware tab, choose the file and press Upload. The page asks for confirmation once. When the download and verification are finished, a "Download complete" window appears, and 5 seconds later the module restarts by itself and installs the image. The page refreshes by itself when the module answers again (about 15 seconds). Do not switch the power off during this time.

If it is refused, the page states the reason, as in "Upload rejected (400 Rejected Package)" — a package for another product, Image CRC Mismatch (422, damaged file), Not An Application (422) and so on.

AT+BOBJVAL gives ACCESS_DENIEDA commandable object (C), or the network has set it Out_Of_Service — check commandable with the flags in AT+BOBJ? (C), and Out_Of_Service with the Status flags on the web Objects tab (out-of-service). AT+BOBJ? does not show Out_Of_Service
CONFIRMED writes always fail with operational-problemThe host does not AT+BWRACK within 750 ms. A late answer gets ERROR:HOST_TIMEOUT
A write gets write-access-deniedAn Input object (writable only while Out_Of_Service), a Value object that is not writable (no W), priority 6, or the host rejected it
A write gets value-out-of-rangeOutside the CSV's min/max, or outside the number of states
The clock is 9 hours offThe sign of the UTC offset. Korea is -540 or "UTC+09:00" (§6.2)
+TIME:SYNCED does not appearWhether the time source accepts that source (AT+TIMESRC?) — the SNTP time source ignores BACnet synchronization. From the second sync from the same source on, there is no URC. Look with AT+TIME?
AT+TIMESRC=SNTP gives INVALID_PARAMETERThe server must be written with it (AT+TIMESRC=SNTP,"pool.ntp.org"). Or the server text is wrong — the : port after a name or IPv4 address can only be a number from 1 to 65535. SNTP is not a deadlock combination: what is refused under SC+STRICT is BACNET and NONE, and SNTP is the way out (§7.6)
AT+BACMODE=SC gives ERROR:URIThe primary hub first (AT+BSCHUB)
AT+BACMODE=SC gives INVALID_PARAMETERThe STRICT + BACNET/NONE deadlock combination (§7.6)
SC stops at CREDENTIALSAT+BSCCERT? — whether all three are PRESENT and KEY is MATCH, and whether CERT is within its validity period
SC gives CERT,0x00000008CA1 is not the issuer of the hub certificate
SC gives TLSThe hub refused this device's certificate (detail is the alert number), or the hub is not TLS 1.3 with EC P-256
SC gives WSThe path in the URI is wrong (detail is the HTTP status)
SC gives TIME_UNKNOWNSTRICT, but there is no time — whether SNTP works: AT+TIME?, +DIAG:SNTP
SC attaches, then drops with CERT_EXPIREDLENIENT's later check — the certificate has expired
AT+BSCCERTW gives NOT_SUPPORTEDThe AT port is 7-bit or XON/XOFF — AT+UART?
BACnet answers nothing although the link is alive+BACMODE:BIP,STOPPED, and the socket in +DIAG:BIP is RETRY — another socket (an AT channel) holds the B/IP port. Once it is released, the module reopens the socket by itself (§3.1)
COV notifications and I-Am do not arriveDCC DISABLE_INITIATION — +DIAG:BACDM (§8.3)
The web does not openWhether AT+WEB? is 1 (the factory default is off), and whether :50003 was added to the address
OTA is refused with PRODUCTIt is a package for another product (for example the SNMP edition)

AT+DIAG?
…

+DIAG:BIP,<rx>,<tx>,<BVLC NAK>,<FD state>,<OPEN|CLOSED|RETRY>,<errno of the last failed open>

+DIAG:BACDM,<DCC state>,<seconds left>,<DCC>,<RD>,<wrong passwords>,<dropped receptions>,<blocked transmissions>,<unsent URCs>
+DIAG:TIME,<SYNCED|UNKNOWN>,<source>,<BACnet received>,<BACnet ignored>,<SNTP received>,<SNTP failures>,…
+DIAG:RESET,<cause>,<restart count>

If rx npdu goes up, the requests are arriving; if it does not, it is a network problem. The web's Diagnostics tab shows the same numbers as JSON. The lines appear, with zeros, even when the BACnet mode is OFF — because "nothing has arrived" is also an answer.

The cause in +DIAG:RESET is POWERON (power) · PIN (RUN pin) · SOFTWARE (a restart the firmware asked for — AT+REBOOT, the web, OTA, factory reset, ReinitializeDevice) · WATCHDOG (the device hung and the watchdog reset it) · DEBUG (debug port) · UNKNOWN, and the Device's Last_Restart_Reason comes from this value (DETECTED_POWER_LOST · COLDSTART · COLDSTART/WARMSTART · HARDWARE_WATCHDOG · UNKNOWN · UNKNOWN). Even if the bootloader installed received firmware after the reset, the cause is that of the reset that led to the installation — if a watchdog reset led to an installation, it is WATCHDOG.

Appendix — a minimal set of settings​

BACnet/IP​

From the factory state, pasting just this makes the module visible to a workstation. (Over AT, with DHCP)

AT+NETMODE=DHCP
AT+SAVE
AT+IP?

AT+BACMODE=BIP
AT+BACDEV=1001,"AHU-1 Controller"
AT+BACPASS="s3cret-Pw"
AT+UTCOFFSET="UTC+09:00"
AT+BOBJADD=AI,1,"Supply Temp",degrees-celsius,P
AT+BOBJADD=AO,1,"Damper",percent,F
AT+SAVE

AT+BOBJVAL=AI,1,21.5
$ python -m bacpypes3 --address 192.168.11.50/24 --instance 999001
> whois
> read 192.168.11.160 analog-input:1 present-value
21.5

If you sell it as your own product, add one more line:

AT+BACVENDOR=<ID>,"<company name>","<model name>"
AT+SAVE

To use the web as well:

AT+WEBUSER="admin"
AT+WEBPASS="your-password"
AT+WEB=1,600
AT+SAVE

BACnet/SC​

On top of the B/IP settings above, at a site that gets its time by SNTP:

AT+TIMESRC=SNTP,"pool.ntp.org"
AT+BSCHUB="wss://hub1.example.com/hub","wss://hub2.example.com/hub"
AT+BSCVALIDITY=STRICT
AT+BACMODE=SC
AT+SAVE

Then upload the three credentials with §7.3 (AT) or §7.4 (web). The module connects as soon as they are uploaded:

+BSCCERTW:CA1,STORED,MATCH,COMPLETE
+BSC:CONNECTED,PRIMARY

The passwords and addresses in the examples are examples only. Do not use them on real equipment.
