Product description​

The EOE-W55RP20_BACnet Module is an embedded communication module built on the WIZnet W55RP20 system-in-package: an RP2040 microcontroller with an on-package W5500 Ethernet controller. A host microcontroller drives the module over a UART AT-command interface. The module is a BACnet server that exposes the host's data points as standard BACnet objects:

  • Up to 256 host-defined objects.
  • Nine object types: Analog, Binary and Multi-state Input, Output and Value.
  • One Device object and one Network Port object.

The host defines the objects in one of two ways: with AT commands, or by importing an object-definition CSV through the web UI or AT. It then updates their values, and it can take part in remote writes (see A.11).

The module runs one BACnet datalink at a time, selected by configuration:

  • BACnet/IP (Annex J), optionally as a foreign device.
  • BACnet/SC (Annex AB), as a hub connector.

All TCP/IP processing runs in the W5500's hardwired TCP/IP engine. TLS 1.3 for BACnet/SC runs in software on the RP2040. The module also has these interfaces, which are not BACnet:

  • an HTTP administration UI protected by a login
  • transparent TCP/UDP socket channels for the host
  • firmware update through a separate bootloader

The module does not route, does not act as a BBMD, and initiates no client requests other than COV notifications.

  • The device limits each reply to the smaller of the client's max-APDU and its own Max_APDU_Length_Accepted. A reply that would need more is answered with Abort SEGMENTATION_NOT_SUPPORTED. Forwarded-NPDU details

A Forwarded-NPDU is treated as a broadcast received from its original source address, not from the BBMD that forwarded it:

  • A confirmed request in it is answered to the original source address.
  • A Who-Is or Who-Has in it is answered as for any local broadcast: by local broadcast, and also through the BBMD while the device is registered as a foreign device.

It is dropped without an answer in these cases:

  • The originator is this device itself (its own broadcast, distributed back by a BBMD).
  • The originator is not a usable single-station address: port 0, 0.0.0.0, a broadcast address, a multicast or reserved address (224.0.0.0 and up), or a loopback address.
  • The originator is on the device's own subnet, unless every answer the NPDU can draw is a local broadcast (an unconfirmed request without SNET, such as Who-Is). Answering such an address directly could hold the device in the W5500's ARP timeout. So an integrator testing through a BBMD from a workstation on the module's own subnet gets an I-Am, but a confirmed request sent that way goes unanswered.

Foreign device registration details

  • The BBMD is configured by IPv4 address or DNS name, with its port and a TTL. The TTL defaults to 300 s.
  • The device registers when B/IP starts and re-registers at half the TTL.
  • A NAK or a timeout is reported to the host (+BIPFD URC) and retried with a back-off: 64 s, doubling to the smaller of the TTL and 10 minutes. A BBMD that comes back after an outage is registered with again within 10 minutes, however long the TTL.
  • A BVLC-Result is taken as the answer to a registration only when it comes from the configured BBMD's address and port. A BBMD that answers from another port (one behind NAT, say) is never heard, and the registration ends FAILED with TIMEOUT.
  • When the BBMD accepts the registration, the device broadcasts an I-Am (V.2).
  • While registered, a broadcast is sent both locally and to the BBMD as Distribute-Broadcast-To-Network.

Failover details

  • The device always tries the primary hub first.
  • Only one hub connection exists at a time.
  • While it is connected to the failover hub, the device probes the primary periodically with a TCP-only connection attempt. When the primary is reachable, the device moves back to it.
  • SC_Hub_Connector_State reports NO_HUB_CONNECTION, CONNECTED_TO_PRIMARY or CONNECTED_TO_FAILOVER.

TLS details

  • TLS 1.3 only, with mutual authentication.
  • Cipher suites: TLS_AES_128_GCM_SHA256 and TLS_AES_256_GCM_SHA384.
  • Key exchange group: secp256r1.
  • Signature algorithm: ecdsa_secp256r1_sha256. RSA certificates and keys are not supported.
  • The hub is authenticated by its certificate chain to a configured issuer and by the certificate's dates, the checks Annex AB.7.4 lists. By default the device does not check the hub certificate's CN or SAN against the URI's host. AT+BSCHOSTCHECK=ON (or the web UI) adds that check: a DNS-named hub must match a DNS SAN, or the CN if the certificate has no SAN; an IPv4 hub must match an iPAddress SAN. A mismatch is reported as CERT with verify flag 0x00000004. SNI is sent for a DNS-named hub, and not for an IPv4 literal, either way.
  • Record sizes: the device accepts TLS records of up to 16,384 octets of plaintext (the TLS 1.3 maximum) and sends records of up to 5,120. Neither max_fragment_length nor record_size_limit is negotiated. The largest record the device sends is its Certificate message, which carries the operational certificate (at most 4,096 octets of DER, below).

Credential details

  • The device holds one P-256 private key, one operational certificate and up to two issuer (CA) certificates.
  • They are uploaded through AT+BSCCERT/AT+BSCCERTW or the web UI, and stored in flash (A/B slots). Each item is at most 4,096 octets as uploaded, PEM or DER; a certificate item holds exactly one certificate.
  • A factory reset erases them, first and checked: if the credential area does not erase (after one retry), the reset stops there - nothing else is reset, the device does not restart, and the host is told (+FACTORY:ERROR,CREDENTIALS) instead of being told the reset completed.
  • No key is generated on the device and no CSR is produced: the private key and the certificates are loaded from outside (AT or the web UI).

BACNET time could only arrive over the hub connection that is waiting for it, and NONE never sets the clock. A.11 Gateway and host interface notes​

The module is a gateway between a host microcontroller and BACnet:

  • The non-BACnet side is the host MCU on a UART AT-command port (115200 8N1 by default).
  • The BACnet side is the datalink selected in A.6.

The BACnet objects are proxies for the host's data points:

  • The host defines each object with AT+BOBJADD or by importing an object-definition CSV. The definition fixes the object's type, instance, name, description, units or number of states, analog min/max, COV_Increment, polarity, Relinquish_Default and the flags below.
  • The host updates Present_Value and Reliability with AT+BOBJVAL, within these limits. A refused update answers ACCESS_DENIED.
    • On a commandable object (AO, BO and MSO always, and a Value object with flag C) the host can set only Reliability. Its Present_Value is what the Priority_Array decides, so a Present_Value from the host is refused.
    • While Out_Of_Service is TRUE, every update is refused, Reliability included (V.1).
Object flagMeaning
C commandableThe object has a Priority_Array, Relinquish_Default and Current_Command_Priority. Always set for AO, BO and MSO. Never allowed for inputs.
W writableA Value object's Present_Value can be written over BACnet. Implied by C on a Value object.
P persistentPresent_Value survives a reset (journal). Non-commandable objects only. The journal takes at most one record per object every 10 s, so a value written less than about 10 s before a power cut can come back as the previous value (A.5, Present_Value persistence). A host that must not lose a value waits 10 s after the write, or sends AT+SAVE, before power may be removed.
F confirmedA remote write is committed only after the host accepts it (below). Without F, the write mode is IMMEDIATE.

Other host interface notes

  • DeviceCommunicationControl and ReinitializeDevice are reported to the host as URCs: +BACDCC and +BACREINIT. The restart follows +BACREINIT.
  • Device identity, datalink, time source and SC credentials are configured through the AT commands and the login-protected web UI. Configuration changes take effect at AT+SAVE or a web save; nothing changes on the network before that. The web UI asks for the password again before a destructive change (the DCC/ReinitializeDevice password, its own account, a factory reset), and those re-confirmations share the login's limit: five wrong passwords lock both out for 60 s and end the session.

Vendor notes (not part of the Annex A form)

These sections describe the implementation in more detail than the Annex A form asks for. They are not form items.

V.1 Out_Of_Service behaviour (all nine host types)​

Out_Of_Service decouples an object from the host, as Clause 12 describes:

  • While Out_Of_Service is TRUE, a Present_Value write is committed inside the module. The host is neither asked nor told, even for an object defined as CONFIRMED (A.11).
  • While Out_Of_Service is TRUE, the host's own updates are refused: Present_Value and Reliability alike (AT+BOBJVAL answers ACCESS_DENIED).
  • When Out_Of_Service returns to FALSE:
    • An Input goes back to the host's last reading.
    • An Output or Value object whose Present_Value changed while it was out of service is reported to the host once, so the host follows the value now in force.

SubscribeCOV details

  • Lifetime 0 means indefinite. Any non-zero lifetime up to 2³²−1 s is accepted.
  • A request with both optional parameters absent is a cancellation. It is answered with SimpleACK even when there is nothing to cancel.
  • A request with Lifetime but without issueConfirmedNotifications is answered with Reject MISSING_REQUIRED_PARAMETER.
  • A subscription to an object that does not exist gets Error OBJECT / UNKNOWN_OBJECT.
  • The subscription table holds 16 entries. When it is full, the request fails with RESOURCES / NO_SPACE_TO_ADD_LIST_ELEMENT.
  • A renewal from the same (address, process identifier, object) replaces the existing entry.
  • An initial notification is sent shortly after the SimpleACK.
  • Subscriptions are held in RAM only. They do not survive a reset, and they are dropped when the active datalink changes.
  • A subscription is also dropped when its object is deleted or redefined (AT+BOBJDEL, AT+BOBJADD or a CSV import). It then disappears from Active_COV_Subscriptions, and no notification tells the subscriber.

DeviceCommunicationControl details

  • ENABLE and DISABLE_INITIATION are accepted. An enable-disable value above 2 gets Reject PARAMETER_OUT_OF_RANGE.
  • Duration:
    • The optional duration is 1 to 65535 minutes. A duration that is absent or 0 means until changed.
    • A duration above 65535 gets Reject PARAMETER_OUT_OF_RANGE.
    • A duration sent with ENABLE is ignored.
  • DISABLE: refused with Error SERVICES / SERVICE_REQUEST_DENIED, and nothing changes. The value is deprecated for a device claiming Protocol_Revision 20 or higher (Clause 16.1), and this device claims 22. The password is checked first, so a request with a wrong or missing password gets PASSWORD_FAILURE. Since the device never enters DISABLE, it always answers Who-Is.
  • DISABLE_INITIATION: the device still answers requests, including I-Am in reply to Who-Is. It stops scheduled I-Am broadcasts, COV notifications and I-Have.
  • Password: set through AT+BACPASS or the web UI, which apply the same check, and stored only as a salted SHA-256 hash. An empty value clears it.
    • The setter allows 1 to 20 octets of UTF-8 with no control characters (C0, DEL or C1 U+0080–U+009F).
    • A request's password is limited in characters: a UTF-8 password of more than 20 characters gets Reject PARAMETER_OUT_OF_RANGE. A password with no character-set octet gets Reject INVALID_TAG. Both apply to ReinitializeDevice as well.
    • Because the setter counts octets, a password with non-ASCII characters is limited to 20 octets, which is fewer than 20 characters.
    • When a password is set, a missing or wrong password returns SECURITY / PASSWORD_FAILURE.
    • When no password is set, any password or none is accepted.

ReinitializeDevice details

  • COLDSTART and WARMSTART restart the device after the SimpleACK has been sent. After a WARMSTART, Last_Restart_Reason reports WARMSTART.
  • START_BACKUP, END_BACKUP, START_RESTORE, END_RESTORE, ABORT_RESTORE and ACTIVATE_CHANGES return SERVICES / OPTIONAL_FUNCTIONALITY_NOT_SUPPORTED.
  • A state value the standard does not define (above 7) is rejected with PARAMETER_OUT_OF_RANGE, before the password is checked.
  • The password is checked first, as for DeviceCommunicationControl, including the Reject for a password of more than 20 characters.
  • ReinitializeDevice is accepted in every DeviceCommunicationControl state.
