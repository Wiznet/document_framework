## 잘 알려진 내용

| 재부팅 관련 문제 |
| ------------------------ |
<details>
<summary>UDP Remote Host와 통신할 수 없는 환경에서 모듈이 재시작됩니다.</summary>

  - WIZ550SR에는 네트워크 단절 또는 데이터 송수신 실패 등으로 네트워크 처리 과정에서 장시간
    대기하는 상태를 방지하기 위한 Watchdog 기능이 적용되어 있습니다.

  - UDP 모드에서 설정된 Remote Host가 네트워크에 존재하지 않거나 네트워크 단절 등의 이유로
    통신할 수 없는 상태에서 Serial 데이터를 전송하면, 네트워크 통신을 위한 처리 과정에서 Timeout까지 대기할 수 있습니다.

  - 이러한 상태가 일정 시간 이상 지속되는 경우 Watchdog에 의해 모듈이 재시작될 수 있으며,
    이는 무한 대기 상태에서 시스템을 복구하기 위한 동작입니다.

  - Remote Host가 일시적으로 존재하지 않거나 통신할 수 없는 상황이 정상적인 사용 환경에
    포함되어 있고, 이러한 상황에서 모듈이 재시작되는 것을 원하지 않는 경우
    **Retransmission Retry Count(RCR)** 값을 조정할 수 있습니다.

|                                                         |
| ------------------------------------------------------- |
| ![](/img/products/wiz550sr/config_tool.png) |
| ConfigTool에서 Retransmission Retry count 값 낮춰서 설정       |

  - **Configuration Tool > Options > TCP timeout > Retransmission Retry count** 값을
    `1`로 설정하면 통신할 수 없는 Remote Host에 대한 Timeout 처리 시간을 줄일 수 있습니다.

  - RCR 값을 낮추면 Watchdog에 의한 재시작 전에 데이터 전송 처리가 Timeout으로 종료되므로,
    Remote Host와 통신할 수 없는 상황에서도 모듈의 재시작을 방지할 수 있습니다.

  > **참고**
  >
  > RCR은 네트워크 통신 실패 시 재전송 횟수를 결정하는 설정입니다.
  > RCR 값을 낮추면 Timeout까지의 대기시간이 짧아지는 대신 재전송 시도 횟수도 감소합니다.
  > **따라서 일반적인 네트워크 환경에서는 기존 설정을 유지하는 것을 권장합니다.**
  > Remote Host가 존재하지 않거나 일시적으로 통신할 수 없는 상황이 정상적인 사용 환경에
  > 포함되어 있고, 해당 상황에서 모듈의 재시작을 원하지 않는 경우 RCR 값을 조정하여 사용하세요.

</details>
